# 팬·관객 밸런스 구현 결과

## 완료 범위
1. 기존 실패 테스트와 공연 진행·결과 적용·화면 연결을 수정했다. 부상 없는 선수는 하루 컨디션 3을 회복하며, 진행이 막힌 날에는 회복하지 않는다.
2. 팬층별 기대와 실제 만족을 계산하고 선수의 선호도·관심도를 별도로 갱신한다. 악역은 호응을 얻어도 마크 선호도가 내려갈 수 있다.
3. 단체 팔로워·만족도·노출량을 저장하고 7일마다 유입과 이탈을 반영한다. 대시보드에는 선수 평균 대신 단체 팔로워를 표시한다.
4. 공연 편성에 티켓 가격 조절과 예상 관객·매출을 연결했다. 결과에는 실제 관객 수와 티켓 가격을 저장한다.

## 핵심 수치와 의도
- 초기 팔로워 2,500명: 마크 875, 캐주얼 1,000, 하드코어 625. 초기 만족도 50.
- 기대치: 42 + 출연 선수 평균(관심도 × 0.28 + |선호도 − 50| × 0.06) + PPV 가산 0/4/6/8.
- 만족도: 50 + (팬층별 공연 평가 − 기대치) × 1.2, 범위 0~100. 공연 평가에서 품질 비중은 마크 70%, 캐주얼 80%, 하드코어 95%; 나머지는 각각 선·악역 연기, 카리스마, 링 심리다.
- 선수 변화는 공연당 각 축 ±3 이내. 같은 날 반복 출연은 추가 변화 0, 7일 이내 재출연은 35%만 반영한다.
- 공연 노출은 90분에서 1, 주간 누적 상한 1.5. 짧은 공연을 반복해 팬을 무한히 늘리는 효과를 제한한다.
- 주간 유입률: 노출 × (0.003 + max(0, 만족도 − 50) × 0.0006).
- 주간 이탈률: 공연이 없으면 0.004, 있으면 0.003 + max(0, 50 − 만족도) × 0.0006. 순변화는 주간 ±2% 이내이고 소수 잔여분을 다음 주에 이월한다.
- 관객 수요는 팔로워·기대·만족·공연 길이·가격 부담·최근 7일 공연 횟수로 계산한다. 대형 경기장을 고른 것만으로 수요가 늘지 않는다.
- 티켓 가격은 기준가의 60~160%. 가격 100% 대비 수요는 60% 가격에서 130%, 160% 가격에서 55%다. 실제 관객은 ±5% 변동 후 수용 인원을 적용한다.

## 12주 실행 검증
매주 20분 경기 6개, 500석, 기본 티켓 $30, 대관료 $4,000. 통제 시나리오는 선수 능력치를 각각 5/10/15로 맞추고 선수당 월급 $1,000, 초기 자금 $100,000으로 비교했다. 실제 선수 시나리오는 생성된 능력치·계약·급여를 사용했다. 매주 공연 실행, 결과 반영, 날짜 진행, 급여, 저장 직렬화와 재로딩을 거쳤다.

| 시나리오 | 12주 팔로워 | 마지막 관객 | 마지막 티켓 매출 | 최종 현금 |
|---|---:|---:|---:|---:|
| 낮은 능력 5 | 2,095 | 187 | $5,610 | $110,200 |
| 보통 능력 10 | 2,608 | 378 | $11,340 | $157,030 |
| 높은 능력 15 | 3,045 | 500 | $15,000 | $194,890 |
| 실제 생성 선수 | 2,639 | 377 | $11,310 | $123,620 |

낮은 능력 시나리오는 마지막 공연의 대관료 차감 후 $1,610으로 주당 환산 급여 $3,000을 충당하지 못한다. 보통은 완만한 성장, 높은 능력은 매진으로 갈린다. 결과에 난수 변동이 있어 위 값은 이번 실행의 관측값이다.

## 검증과 호환성
- Unity CLI EditMode 테스트 238개 전체 통과, 실패 0. 컴파일 오류 0.
- 중복 결과 적용, 잘못된 수치의 원자적 거부, 주간 중복 지급, 날짜 일괄 진행, 기존 저장 이전, 티켓 가격 저장과 확정 후 잠금, 실제 UI 데이터 연결을 검증했다.
- 기존 저장은 팔로워를 한 번 초기화하고 기존 공연 결과에 보상을 소급 지급하지 않는다. 과거 티켓 비율 필드가 없으면 100%로 처리한다.
- Unity MCP 연결 설정을 제거했다. 이후 Editor 제어·컴파일·검증은 Unity CLI만 사용한다. CLI용 com.unity.pipeline은 유지한다.
- 증빙: artifacts/balance/editmode-results.json 및 fans-12-weeks-*.csv.

현재 수요는 단일 지역 시장 모델이다. 지역별 팬 기반은 지역 데이터 도입 시 분리한다. 이번 검증은 Editor 테스트와 화면 확인이며 배포 빌드 검증이나 장기 플레이테스트를 대체하지 않는다.
