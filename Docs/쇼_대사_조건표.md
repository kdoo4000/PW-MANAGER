# 쇼 대사·스크립트 조건표

기준: 2026-09-03 현재 프로젝트 소스. 아래 문장은 새로 쓴 예시가 아니라 구현된 문구다. 특수 상황 해설 추가분까지 반영했다.

범위: 경기 해설, 프로모 대사 생성·대체 문구, 쇼 종료 문구, 별도 프로모 템플릿. 메뉴 이름·일반 버튼·평가 사유·테스트용 예문은 제외했다. 실행 중 자동 생성되어 저장된 개별 프로모 대사까지 모은 목록은 아니다.

## 1. 문장 안의 변수

| 표기 | 실제 들어가는 값 |
|---|---|
| `{actor}` | 해당 장면을 주도하는 선수 이름. ID가 없으면 `선수` |
| `{target}` | 해당 장면의 상대 이름. ID가 없으면 `상대` |
| `{spot}` | 프로듀싱에서 입력한 스팟 원문. 앞뒤 공백만 제거 |
| `{name}` | 프로모 첫 번째 출연자의 링네임. 비어 있으면 본명 |
| `{winnerNames}` | 경기 결과에 기록된 직접·간접 승자의 이름을 ` & `로 연결 |
| `{stars}` | 별점. 소수점 최대 두 자리로 표시하여 `.25`, `.75` 보존 |
| `{netIncome}` | 쇼 순손익. 천 단위 구분 기호를 넣은 정수 |

기본 경기 흐름의 `{actor}`는 첫 진영의 첫 선수, `{target}`은 두 번째 진영의 첫 선수다. 반격과 두 번째 주도권 장면에서는 두 선수의 역할이 바뀐다. 결말 장면의 `{actor}`는 결정 선수(`FinishPerformerId`, 없으면 `WinnerId`), `{target}`은 패배 대상이다. 첫 두 선수 외의 참가자도 한 번씩 주도권 장면에 등장하며, 공격 대상은 다른 진영에서 고른다. 모든 선수 조합을 전부 재생하지는 않는다.

같은 결과 시드와 입력이면 같은 문장이 선택된다. 시작·재정비·승부 직전 및 스타일별 공방은 여러 문장 중 하나를 선택한다. 관전 화면은 유효한 저장 해설·장면을 재사용한다.

## 5. 선수 관계·과거 대결

시작 직후 최대 한 문장만 출력한다. 위에서부터 우선 적용하므로 태그팀 기록이 있으면 재대결 문장은 나오지 않는다.

| 우선순위 / ID | 출력 조건 | 문장 |
|---|---|---|
| 1 / H01 | 첫 선수와 상대가 함께 포함된 태그팀 기록이 있고, 해당 팀 상태가 `Disbanded` | 한때 같은 태그팀이었던 두 선수입니다. 서로의 움직임을 잘 알고 있겠죠. 오늘은 맞은편에서 승부를 겨룹니다! |
| 2 / H02 | 두 선수가 함께 포함된 태그팀 기록이 있고, 상태가 `Disbanded`가 아님 | 같은 팀으로 호흡을 맞춘 두 선수가 오늘은 맞붙습니다. 서로를 잘 아는 만큼 수 싸움이 중요하겠습니다! |
| 3 / H04 | 위 태그팀 기록이 없고, 직전 맞대결에서 두 선수 중 한 선수가 승리. `{패한 선수}`는 반대 진영의 선수 이름 | {패한 선수}, 지난 맞대결에서는 패했습니다. 오늘은 설욕할 수 있을까요? |
| 4 / H03 | 위 태그팀 기록이 없고, 다른 쇼의 직전 맞대결 기록은 있으나 두 선수 중 승자를 확인할 수 없음. 무승부 등 | 이전에 맞붙었던 두 선수가 다시 만났습니다! 지난 대결의 경험을 어떻게 활용할지 지켜보시죠. |
| — | 저장 데이터나 두 선수 ID가 없거나, 위 기록이 없음 | 출력하지 않음 |

현재는 일반적인 라이벌리 수치, 스테이블 동료, 선악 성향, 챔피언 관계 등에 대한 별도 **고정 경기 해설**은 없다. 태그팀 기록은 두 선수가 포함된 첫 번째 기록을 검사한다.

## 6. 경기 실행 중 사건

실제 경기 결과의 `ExecutionEvents`에 있는 사건만 순서대로 출력한다. 해설이 부상이나 실수를 새로 발생시키지는 않는다.

| ID | 출력 조건 | 문장 |
|---|---|---|
| E01 | 부상 사건 / `Injury` | 선수에게 부상이 발생했습니다. 경기 상황을 주의 깊게 지켜봐야겠습니다. |
| E02 | 실수 사건 / `Mistake` | 아, 동작이 매끄럽게 이어지지 않았습니다! 흐름을 다시 잡아야 합니다. |
| E03 | 부상·실수 이외의 실행 사건 / 기본 분기 | 지금 장면, 훌륭했습니다! 이번 경기에서 기억에 남을 순간입니다. |

| F01 | 핀폴 / `Pinfall` 또는 기본 분기 | {actor}, 커버합니다! 하나, 둘, 셋! {target}, 어깨를 들지 못했습니다! |
| F02 | 서브미션 / `Submission` | 항복을 받아냈습니다! {actor}, 서브미션 승리입니다! |
| F03 | 롤업 / `RollUp` | 기습적으로 말아 넣습니다! 하나, 둘, 셋! {actor}, 롤업으로 승리를 가져갑니다! |
| F04 | 반칙 / `Disqualification` | 심판이 경기를 중단합니다! 반칙 판정입니다. 승자는 {actor}입니다! |

프로듀싱에서 정한 결과가 실제 경기 결과에 기록되고, 해설은 그 결과를 읽는다. 스타일이나 관계 때문에 승패 문장이 다른 결과로 바뀌지는 않는다. 편성 시 결말 선택 가능 여부는 경기 구성·기믹 규칙이 별도로 제한한다.

## 8. 사용자가 편집하는 경기 스팟

| ID | 출력 조건과 위치 | 문장 |
|---|---|---|
| S01 | 경기 전 스팟이 비어 있지 않음. 시작 해설 전에 출력 | 자, 이 장면 보시죠! {spot} |
| S02 | 경기 중 스팟이 비어 있지 않음. 두 번째 주도권 장면 다음에 출력 | 자, 이 장면 보시죠! {spot} |
| S03 | 경기 후 스팟이 비어 있지 않음. 결말 해설 다음에 출력 | 자, 이 장면 보시죠! {spot} |

세 칸 모두 같은 도입 문장을 쓴다. 스팟 본문은 자동으로 다시 쓰거나 주체를 붙이지 않고 그대로 보여준다. 예를 들어 입력한 거절이 수락으로 바뀌지 않도록 하는 구조다.

### 기본 출력 순서

경기 전 스팟(선택) → 시작 → 관계·설욕전(선택) → 시작부 특수 상황(최대 2개) → 첫 선수 주도권 → 상대 반격 → 상대 주도권 → 낮은 컨디션(선택) → 경기 중 스팟(선택) → 실제 실행 사건(있는 만큼) → 재정비 → 피니시 시도 → 결말 → 이변 승리(선택) → 경기 후 스팟(선택).

일반 경기의 총 재생 시간은 실제 경기 길이 × 6초를 60~120초 범위로 제한하고, 메인 이벤트는 150초다. 주도권 장면의 시간 가중치는 1, 결말은 5, 나머지는 3이다. 이는 대사 분기와 별도로 장면 길이를 정하는 규칙이다.

## 9. 프로모: 고정 대체 문구

자동 생성 모델이 없거나, 생성 실패·검증 실패가 발생하면 아래 대체 스크립트를 사용한다. 관전 화면에서도 저장된 프로모 문장이 없거나 비어 있으면 같은 대체 스크립트를 사용한다.

| ID | 출력 조건 | 종류 | 문장 |
|---|---|---|---|
| P01 | 입력한 필수 스팟이 하나 이상 있음 | 현장 행동 / `Action` | `{spot}` 원문 그대로. 오프닝·중반·마무리 순서로 비어 있지 않은 칸만 출력 |
| P02 | 필수 스팟이 없고 출연자가 있음 | 대사 / `Dialogue` | {name}가 자신의 뜻을 관중에게 분명히 전합니다. |
| P03 | 필수 스팟도 출연자도 없음 | 현장 행동 / `Action` | 준비된 영상이 상영됩니다. |

필수 스팟이 있으면 P02·P03은 추가하지 않는다. 이 대체 문구는 모두 강도 2로 생성된다. P02는 현재 코드상 `Dialogue`로 분류되지만, 실제 문장 자체는 인물의 직접 발언이 아니라 행동을 서술하는 형태다.

## 12. 별도 보유 템플릿: 스테이블 영입

`StableRecruitment.asset`은 문장을 완성해 둔 대사집이 아니라 사건 흐름을 적어 둔 그래프다. 현재 경기·프로모 관전 코드에서 이 자산을 읽어 대사를 실행하는 연결은 확인되지 않았다. 아래 영어는 자산의 원문이며, 한국어 조건 설명만 정리했다.

| 노드 ID | 진입 조건·흐름 | 자산 제목 | 설명 원문 |
|---|---|---|---|
| start | 시작 | Recruitment Begins | The stable or tag team calls out a prospective member. |
| approach | start 다음, `Call Out` | Make the Approach | The recruiting side explains why the target belongs with them. |
| offer | approach 다음, `Pitch` | Present the Offer | 비어 있음 |
| response | offer 다음, `Decision` | Target Responds | Book the target to accept, reject, or keep negotiating. |
| join_change | response에서 `Accept` 선택 | Membership Change | Queue the target joining the recruiting team or stable. |
| joined | join_change 다음, `Apply` | Recruitment Accepted | The target joins. Evaluation changes the quality and side effects, not this booked result. |
| rejected | response에서 `Reject` 선택 | Recruitment Rejected | The target refuses the offer. The refusal may create or intensify conflict. |
| pending | response에서 `Negotiate` 선택 | Negotiations Continue | No membership change occurs yet; the open offer can continue in a later promo. |

## 13. 추가된 특수 상황 해설

시작부는 다음 표의 순서대로 조건에 맞는 문장을 최대 두 개만 선택한다. 관계·설욕전 해설은 별도 한 줄이다. 새 해설을 넣어도 경기 전체 재생 시간은 기존과 동일하다.

스타일 분류는 4절의 매핑을 그대로 사용한다. 조건이 셋 이상 겹치면 뒤쪽 문장은 생략된다. 예를 들어 래더 경기에서 연승 조건까지 맞으면 경력·체중·스타일 대결 문장은 추가하지 않는다. 실제 사다리 설치·케이지 등반·테이블 충돌 같은 행동은 이 문장들로 새로 발생했다고 주장하지 않는다.

| 시점 / ID | 출력 조건 | 문장 |
|---|---|---|
| 경기 중 / X11 | 참가자 중 저장된 컨디션이 50 미만인 첫 선수. 실제 동작 실수·부상 판정과는 별개 | {선수명}, 오늘 컨디션이 좋지 않습니다. 긴 승부가 된다면 체력 배분이 중요하겠습니다. |
| 결말 후 / X12 | 참가자 2명, 무승부 아님, 승자와 패배 대상이 서로 다르고 실제 참가자이며, 패배 대상의 위상이 승자보다 25 이상 높음 | {승자명}, 위상의 차이를 뒤집었습니다! 더 높은 평가를 받던 상대를 꺾는 값진 승리입니다! |

X12는 다자전·태그 경기에서 한 선수만 비교해 팀 전체의 이변으로 오해하지 않도록 2인 경기로 제한한다. 경기 후 스팟이 있으면 X12 뒤에 나온다. 사전 해설에는 이번 승부의 결과를 노출하지 않는다.

| 컨디션·위상 | `Condition.Condition`, `Status.StatusValue` 저장. 현재 값이며, 모든 과거 경기의 이 값들이 별도 스냅샷으로 남는 것은 아님 |
| 승패·진영 | `MatchResults`의 승리 진영, 결정 선수, 직접·간접 승패 대상, 참가 진영 프로필 저장 |
| 연승·설욕전 | 별도 상태값을 추가하지 않고 위 경기 기록에서 계산. 같은 쇼 기록은 제외. 과거 결과를 다시 생성할 때 현재 결과 ID가 목록에 있으면 그 항목 이전 기록만 사용 |
| 연승 중단 | 가장 최근 참가 기록부터 역순으로 승리한 경기만 센다. 패배·무승부·승리 확인 불가 기록에서 중단. 태그팀 간접 승리도 포함 |
| 태그팀 관계·호흡 | `TagTeams`의 구성·상태·호흡 저장. 경기 결과에는 `ParticipantProfiles`의 대표 팀 ID와 실제 적용 호흡 수치 저장 |
| 기믹·스팟 | `MatchPlanState.MatchGimmickId`, `OpeningSpot`, `MiddleSpot`, `ClosingSpot` 저장 |
| 이변 여부 | 2인 경기의 실제 결과와 해설 생성 시점의 위상을 비교. 별도 이변 플래그는 추가하지 않음 |
| 완성된 해설 | `MatchResultState.SimulationBeats`, `NarrativeLines`에 장면·문장 저장. 정상 저장된 해설은 재관전 시 재사용하므로 이후 선수 상태가 바뀌어도 문장이 바뀌지 않음 |
| 정식 게임 | `GameSave` 전체가 저장 파일로 기록됨 |
| `Show Test` 씬 | 임시 메모리 세션. 실제 저장 파일에는 기록하지 않으며, 씬 종료·새 쇼 초기화 시 테스트 기록은 유지되지 않음 |

난입·악수·배신·사다리 설치 등은 조건만 보고 임의로 새 사건으로 만들어 내지 않는다. 이번 추가분은 사실 기반 상황 설명이며, 구체 행동은 편집한 스팟 또는 실제 실행 사건 기록이 있어야 한다. 같은 쇼 재출전에 따른 누적 피로 전용 해설은 이번에 추가하지 않았다.

새 문장은 새로 생성하는 경기 해설에 적용된다. 이미 저장된 기존 경기의 대사는 자동 교체하지 않는다.

## 15. 태그팀·다인전 해설

두 명 이상으로 구성된 진영이 있으면 팀전, 진영이 3개 이상이면 다인전이다. 3개 이상 팀의 대결도 별도로 안내한다. 시작·중반·종료에서 각 조건에 맞는 두 문장 중 하나를 선택한다. 실제 태그 교대·세이브·난입 사건은 새로 만들어내지 않는다.

| 출력 조건 | 문장 |
|---|---|
| 시작 · 3개 이상 진영이며 팀전 | {진영 수}개 팀이 맞붙습니다! 동료와 호흡을 맞추면서 다른 팀의 움직임도 살펴야 합니다. |
| 시작 · 3개 이상 진영이며 팀전 | 여러 팀이 겨루는 경기입니다. 자기 팀의 공방에만 집중하다가는 다른 팀에 기회를 줄 수 있겠죠! |
| 시작 · 3개 이상 진영이며 개인전 | {참가자 수}명이 각자 승리를 노립니다! 눈앞의 상대뿐 아니라 다른 선수들의 위치도 중요합니다. |
| 시작 · 3개 이상 진영이며 개인전 | 한 명만 상대하면 되는 경기가 아닙니다! 공격할 때도 다른 쪽에서 생길 빈틈을 생각해야겠죠. |
| 시작 · 2개 진영의 팀전 | 팀 대 팀의 승부입니다! 개인의 기량과 함께 동료끼리 호흡을 맞추는 능력이 중요하겠습니다. |
| 시작 · 2개 진영의 팀전 | 혼자 잘하는 것만으로는 부족합니다. 서로의 장점을 살려줄 조합은 어느 쪽일까요? |

| 중반 · 2개 진영의 팀전 | 동료의 상태를 살피는 판단도 필요합니다. 팀 전체의 여력을 어떻게 나눠 쓸지 보시죠. |
| 중반 · 2개 진영의 팀전 | 서로의 빈틈을 얼마나 잘 보완하느냐가 중요합니다. 개인전과는 다른 판단이 필요한 순간입니다. |
| 종료 · 승자가 2명 이상 팀 소속, 무승부 제외 | 결정적인 승부가 팀의 승리로 이어집니다! 함께 나선 동료들도 이 결과를 가져갑니다. |
| 종료 · 승자가 2명 이상 팀 소속, 무승부 제외 | 팀 대결의 승자가 정해졌습니다! 오늘의 승리는 동료들과 함께 기록됩니다. |
| 종료 · 개인 다인전, 무승부 제외 | 여러 상대와 겨룬 끝에 승자가 나왔습니다! 복잡한 승부에서 끝내 결과를 가져갑니다. |
| 종료 · 개인 다인전, 무승부 제외 | 여러 선수가 맞붙은 다인전, 마지막 승부를 결정지은 선수가 승리를 가져갑니다! |

팀전·다인전의 시작 특수 상황은 경기 형식 안내 외 최대 1개다. 선수 관계 해설은 별도다. 장면이 늘어도 전체 재생 시간은 일반 경기 60~120초, 메인 이벤트 150초로 유지한다. 새 대사는 새로 생성하는 경기 해설에 적용되며 이미 저장된 해설을 덮어쓰지 않는다.

## 16. 무브셋 수행 결과별 해설

1. `{actor}의 {기술 이름}!`

### 수행 판정과 저장 범위

- 기술의 기존 타격·파워·테크니컬·공중기 가중치로 주체의 수행 능력을 계산하고, 상대의 셀링 능력을 함께 사용한다.
- 각 선수의 컨디션과 해당 경기의 스태미나 페널티를 차감한다. 컨디션 차감은 `(100 - 컨디션) / 20`이며 결과는 최소 0이다.
- 조정된 수행 능력과 셀링의 평균을 기존 스팟 확률식에 넣는다. 난도는 기술 수행 난도와 셀링 난도의 평균이다. 별도 결과 시드를 사용하므로 다른 경기 판정을 다시 굴리지 않는다.
- 네 등급은 **기술의 수행 품질**이다. 실패가 자동으로 상대의 전술적 카운터를 뜻하거나, 대실패가 자동으로 부상을 뜻하지 않는다.
- 기술 결과가 승패·별점·부상·컨디션 비용에 추가 영향을 주지는 않는다. 전체 재생 시간도 기존 범위를 유지한다.
- `MatchResultState.MoveResults`에 기술 ID·당시 이름·주체·대상·시그니처/피니셔 구분·수행 점수·셀링 점수·결과 등급을 저장한다. 완성된 대사와 장면도 기존 `NarrativeLines`·`SimulationBeats`에 저장한다.
- 구형 기록에 무브 결과가 없으면 임의로 결과를 만들지 않는다. 새로 진행하는 경기부터 적용하며, 저장된 해설은 그대로 재생한다.
- 현재 카탈로그에 없는 확장 기술은 저장된 기술 이름과 공통 동작 문구를 사용한다. 정의 자체를 찾을 수 없는 기술은 새 수행 판정에서 생략한다.
- 일반 게임은 기존 저장 흐름을 따르고, 쇼 테스트 씬은 기존과 같이 임시 데이터만 사용한다.
