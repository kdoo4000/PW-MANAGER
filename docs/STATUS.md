# PW MANAGER — STATUS

> 마지막 문서화: 2026-08-31. Notion 개발 현황과 현재 저장소의 관련 코드 존재 여부를 대조한 상태다. 테스트 수치는 이번 갱신에서 다시 실행하지 않았으므로 마지막 확인 기록을 그대로 표시한다.

## 현재 단계

1차 프로토타입의 개별 기반 시스템은 상당 부분 존재하지만, 게임 시작 → 날짜 진행 → 쇼 개최 → 결과 반영을 하나의 플레이 가능한 흐름으로 연결하는 작업은 아직 남아 있다.

## 구현 상태

- 정적 콘텐츠: 이름, 기술, 특성, 스타일, 공연장, 경기 형식과 기믹 카탈로그 기반이 있다.
- 선수 생성: 시드 기반 후보 생성과 로스터 보장 조건이 구현되어 있다.
- 게임 시작·저장: 초기 로스터·계약·부서·공연장·시즌 일정 조립과 JSON 저장 기반이 있다.
- 시즌 일정: 정기 쇼·PPV와 편성 마감일 생성 기반이 있다.
- 시간 진행: 일 단위 진행, 급여와 계약 만료 처리 기반이 있다.
- 쇼·매치 편성: 매치·프로모 타임라인과 주요 검증을 담당하는 `ShowPlanningService`가 있다.
- 경기 평가: `MatchEvaluator`와 관련 테스트가 있다.
- 프로모 평가: `PromoEvaluator`와 관련 테스트가 있다.
- 쇼 실행: `ShowExecutionService`가 확정된 타임라인의 매치와 프로모를 순서대로 평가해 단일 `ShowResultState`를 생성한다. 이벤트별 시드는 쇼 버전·입력 시드·이벤트 ID에서 결정되고, 혼합 타임라인 순서는 `TimelineResultIds`에 보존된다.
- 쇼 결과 반영: `ShowResultApplicationService`가 `ResultApplicationContext`에서 선수 컨디션·출전 기록, 재정 거래, 일정 완료 상태를 모두 검증한 뒤 원자적으로 적용한다. 적용 키로 중복 적용을 거부하며, 결과·거래·처리 키는 저장·복원된다.
- 저장: `SaveService`가 쇼 결과 목록과 결과 반영에 쓰는 저장 상태를 저장·복원한다.
- UI: 타이틀, 새 게임, 대시보드와 선수 프로필 화면 기반이 있다.

## 확인된 연결 공백

- 날짜 진행이 예정된 쇼 개최를 호출하고 결과 저장까지 마치는 플레이 가능 핵심 루프가 연결되지 않았다.
- 팬 반응, 평론가 평가와 스팟은 후속 콘텐츠 단계다.

## 최근 검증 기록

- 2026-08-31: Unity Editor에서 `ShowExecutionServiceTests` 5/5 통과. 확정 카드 실행, 시드 재현성, 잘못된 편성, 미확정 쇼, 중복 실행을 검증했다.
- 2026-08-31: 전체 EditMode 156개 중 153개 통과. 실패 3건은 기존 `WrestlerGeneratorTests.InitialCandidates_MeetConfirmedCompositionRules`의 시드별 능력 하한이며, 쇼 실행 변경과 무관하다.
- 2026-08-31: `ShowResultApplicationServiceTests`는 성공·중복 적용·사전 검증 실패·누락 결과·JSON 왕복을 다룬다. 이 환경에서는 프로젝트가 열린 Unity Editor 때문에 배치 모드 재실행이 차단되어, 이번 갱신에서 재실행하지 못했다.

## 다음 한 작업

날짜 진행에서 예정된 쇼를 실행하고 그 결과를 한 번만 저장·반영하는 경로를 연결한다.

### 완료 조건

- 예정된 쇼 날짜에만 `ShowExecutionService`를 호출한다.
- 생성된 `ShowResultState`를 저장하고 `ShowResultApplicationService`로 한 번만 반영한다.
- 같은 일정 또는 같은 쇼 결과를 다시 처리하면 중복 실행·반영 없이 명시적으로 실패한다.
- 예정 쇼 없음, 미확정 쇼, 실행·반영 실패가 날짜·선수·재정·일정에 부분 변경을 남기지 않는다.
- 팬·스토리·타이틀·토너먼트 반영과 새 UI는 이번 작업 범위에서 제외한다.

## 이어지는 작업 순서

1. 날짜 진행에서 예정된 쇼 개최 호출
2. 게임 시작부터 결과 저장까지 핵심 루프 통합 테스트
3. 스팟, 평론가 평가와 팬 반응 연결
