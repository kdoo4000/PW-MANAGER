# PW MANAGER

프로레슬링 단체의 로스터와 일정을 관리하고, 직접 흥행을 기획해 결과를 만들어 가는 운영 시뮬레이션 게임입니다.

> 현재 개발 중인 개인 프로젝트입니다. 일부 콘텐츠와 UI는 변경될 수 있습니다.

## 프로젝트 소개

플레이어는 프로레슬링 단체의 매니저가 되어 선수 계약, 흥행 일정, 경기 카드와 프로모를 관리합니다. 선수의 능력치와 컨디션, 경기 규칙, 연출 선택이 흥행 결과에 반영되며, 결과는 다시 선수와 단체의 상태에 영향을 줍니다.

- **프로젝트명:** PWMANAGER
- **장르:** 프로레슬링 단체 운영 시뮬레이션
- **개발 형태:** 개인 프로젝트
- **버전:** 0.1.0 (개발 중)
- **빌드 플랫폼:** Windows PC 기준 개발 및 검증

## 개발 환경

- **Engine:** Unity 6.0 (`6000.5.4f1`)
- **Language:** C#
- **Render Pipeline:** Universal Render Pipeline (URP)
- **UI:** Unity UI Toolkit
- **Input:** Unity Input System
- **AI Runtime:** LLMUnity 기반 로컬 LLM 연동
- **Test:** Unity Test Framework / EditMode 테스트

## 주요 기능

- 선수와 매니저 로스터 조회 및 프로필 관리
- 단체 생성, 초기 계약 제안, 경기장 선택
- 정규 흥행과 PPV 일정 생성 및 관리
- 경기와 프로모를 조합한 흥행 카드 편성
- 타임라인 드래그를 통한 세그먼트 순서 조정
- 경기 형식, 기믹, 승자, 피니시, 주요 스팟 설정
- 선수 능력치와 연출 조건을 반영한 경기·프로모 평가
- 관중 반응, 부상, 선수 상태, 재정 변화를 포함한 결과 적용
- 다중 슬롯 저장 및 불러오기

## 조작 방법

| 조작 | 기능 |
| --- | --- |
| 마우스 왼쪽 클릭 | 메뉴 선택, 버튼 실행, 선수 및 흥행 정보 확인 |
| 마우스 드래그 | 흥행 타임라인의 경기·프로모 순서 변경 |

별도 키보드 조작 없이 UI에서 주요 기능을 사용할 수 있도록 구성했습니다.

## 구현한 시스템

### 흥행 기획과 검증

경기와 프로모를 하나의 타임라인에 배치하고 전체 방송 시간을 관리합니다. 선수 중복 출연, 계약 상태, 출전 가능 여부, 경기 형식별 인원과 팀 구성, 기믹과 피니시의 호환성을 흥행 확정 전에 검증합니다.

### 경기·프로모 시뮬레이션

선수 능력치, 경기 스타일, 연출 스팟과 프로모 목적을 바탕으로 결과를 계산합니다. 시뮬레이션 결과는 평점과 서사뿐 아니라 모멘텀, 컨디션, 만족도, 부상과 재정 상태에도 반영됩니다.

### 시즌과 일정 관리

정규 흥행 및 PPV 정책을 기준으로 시즌 일정을 생성합니다. 날짜 진행 과정에서 예정된 흥행과 필수 의사결정을 확인해 게임 상태가 잘못 진행되지 않도록 제어합니다.

### 데이터 기반 콘텐츠

경기 형식, 경기 기믹, 기술, 선수 특성, 경기장 등의 정적 콘텐츠를 데이터로 분리했습니다. 핵심 규칙과 화면 로직의 결합을 줄여 콘텐츠 수정과 검증이 쉽도록 구성했습니다.

### 저장 시스템

게임 상태를 JSON으로 저장하며 다중 슬롯, 백업 파일, 저장 버전 마이그레이션을 지원합니다. 임시 파일 작성과 역직렬화 검증을 거친 뒤 기존 파일을 교체해 저장 중 오류로 인한 데이터 손상 가능성을 줄였습니다.

### 계층 분리

프로젝트 코드를 `Domain`, `Data`, `Infrastructure`, `Presentation` 어셈블리로 나눴습니다. 게임 규칙은 Unity 화면 코드와 분리해 EditMode 테스트에서 빠르게 검증할 수 있도록 설계했습니다.

## AI 활용 방식

AI는 구현과 검증을 보조하는 도구로 활용했습니다.

- 기능 설계 초안과 예외 상황 점검
- 반복 코드 작성 및 리팩터링 후보 검토
- 테스트 케이스 보완과 오류 원인 탐색
- 로컬 LLM을 이용한 프로모 대사와 상황 연출 생성

게임 규칙과 결과 계산은 직접 작성한 코드가 담당합니다. LLM 출력에는 JSON 스키마, 등장인물 ID, 필수 연출 조건을 검증하며, 생성 실패나 잘못된 응답이 발생하면 규칙 기반 대체 연출을 사용합니다. 따라서 AI 기능의 상태와 관계없이 핵심 게임 흐름은 유지됩니다.

## 개발 중 해결한 문제

### 복잡한 흥행 조합의 무결성

경기 형식, 팀 구성, 기믹, 피니시와 선수 상태가 서로 영향을 주면서 잘못된 카드 조합이 만들어질 수 있었습니다. 흥행 확정 단계에 공통 검증 서비스를 두고 모든 조건을 한곳에서 확인하도록 개선했습니다.

### 저장 중 데이터 손상 가능성

기존 저장 파일에 바로 쓰면 작업 중 오류가 발생했을 때 세이브가 손상될 수 있었습니다. 임시 파일 저장, 직렬화 결과 검증, 기존 파일 백업, 원자적 교체 순서로 저장 흐름을 구성했습니다.

### 생성형 AI 응답의 불확실성

LLM 응답은 형식 오류나 필수 정보 누락이 발생할 수 있습니다. 응답 길이와 구조, 화자, 필수 비트를 검증하고 실패 시 규칙 기반 결과로 전환해 게임 진행이 중단되지 않도록 처리했습니다.

### UI와 게임 규칙의 결합

화면 코드에서 규칙까지 함께 처리하면 기능 확장과 테스트가 어려워졌습니다. 도메인 서비스를 별도 어셈블리로 분리하고 UI는 입력과 표시를 담당하도록 역할을 정리했습니다.

## 폴더 구조

```text
Assets/
├─ Game/
│  ├─ Domain/          # 게임 상태, 규칙, 평가 및 진행 서비스
│  ├─ Data/            # 정적 콘텐츠 정의, 로딩, 생성, 검증
│  ├─ Infrastructure/  # 저장 등 외부 입출력
│  ├─ Presentation/    # UI Toolkit 화면과 사용자 입력
│  ├─ Editor/          # 콘텐츠 제작 및 미리보기 도구
│  └─ Tests/           # EditMode 테스트
├─ Scenes/             # 실행 씬
└─ LLMUnity/           # 로컬 LLM 연동 런타임

Packages/              # Unity 패키지 설정
ProjectSettings/       # Unity 프로젝트 설정
Docs/                  # 게임 콘텐츠 및 규칙 문서
```
